# 新3Dプロダクト開発計画

2026-09-05 / 飲もポリー 3D / repository: nomopoly-3d

## 目的と分離

飲もポリーの全既存機能を引き継ぎ、オリジナルの3D飲み屋街で同一端末・2〜6人が遊ぶ別プロダクトにする。旧サービスは継続運用する。最初は40マスの順序、価格、カードとルールを維持する。目的地・分岐・到着報酬は将来の別フェーズ。

独立したGitリポジトリ、lockfile、検証CI、保存キーを使用する。共有パッケージ化のために旧版を変更しない。バグ修正を両方へ適用する場合は別々に検証・リリースする。新リポジトリは非公開を初期設定とし、公開配信は別途設定する。

## 実装済みの初期試作

- 3D描画はルール処理から分離。Appが既存GameStateを管理し、WorldSceneが表示する。
- 既存useTokenAnimationが移動経路を決め、3Dがマス間を補間。大きな位置ジャンプはスナップする。
- 3Dシーンを遅延ロード。WebGL非対応・描画失敗時はユーザーが平面表示に切り替えて継続できる。
- 40マス、所有とレベル・抵当を反映する建物、プレイヤーの駒、公園。
- カメラの回転・拡大・追従・全体表示。正確に選択できるHTMLのマス一覧も提供する。
- タイトル・配色は旧版の飲もポリー(クリーム地・黒罫線・緋色・金)を踏襲する。
- 初期素材は手続き的な形状で、追加のモデルダウンロード不要。Blenderは正式アセット制作フェーズで使用する。

## 機能引き継ぎ表

| 機能群 | 実装状況 | 検証範囲 |
| --- | --- | --- |
| 人数・名前・終了条件・成長率設定 | 既存UIを継承 | 開始テスト、ブラウザ起動 |
| 40マス・サイコロ・移動・ターン | 既存ルール＋新3D表示 | 経路整合、固定出目、購入、次ターン |
| 土地購入・建設・改装・所有者 | 既存操作＋3D建物反映 | 購入テスト。改装の全組合せは未検証 |
| 飲み代・倍率・免除・先送り | 既存処理・UIを継承 | 計算設定、先送り／解消。全コンボは未検証 |
| カード・指名・物件選択・勝敗指定 | 既存処理・UIを継承 | ソース一致。カード別の全経路は未検証 |
| 交渉・物件交換・抵当・返済 | 既存処理・UIを継承 | ソース一致。全交渉条件は未検証 |
| タクシー待機所・チケット・ワープ | 既存処理・UIを継承 | ソース一致。3Dワープ演出は追加検証予定 |
| 脱落・終了・順位 | 既存処理・UIを継承 | ソース一致。長時間プレイは未検証 |
| 保存・再開・音・ログ | 既存処理＋独立キー | 保存分離、壊れたセーブ、ブラウザ再開 |

ソース一致は機能の全動作保証ではない。正式リリース前に全カード・交渉・終了条件のシナリオ検証を追加する。

## 次の段階

1. 実機評価: iPhone Safari / Android Chromeで操作、読込、発熱、バックグラウンド復帰を測定。対象機種を固定し、30fps以上を暫定目標にする。
2. 体験調整: 移動・着地・カードの通知順、ターン交代、地名ラベルの視認性。回転時の誤タップ、低性能端末での影と描画負荷を調整。
3. 機能検証: 全カード、免除、交渉、抵当、脱落、同時脱落、再開、連打の回帰テスト。
4. 美術: オリジナルの建物・キャラクターをBlenderで作成しGLB出力。低ポリゴン、共通素材、軽量テクスチャを基本に、段階的に差し替える。
5. 演出: 歩行・喜び・驚き、建設時の演出、短いカメラワーク。演出完了をルール適用条件にしない。
6. 新プロダクト専用の公開先とドメインを設定し、旧版のURL・保存・配信が影響を受けないことを確認して公開する。

## 技術的な留意点

- Three.js本体を含む3Dチャンクは大きいためゲーム開始時に遅延ロード。現状の大きさはビルド出力で確認する。
- 影は1024px、DPR上限1.5。実機の性能目標達成は未確認。
- オンライン同期・サーバーは含まない。プレイヤーが同じ端末で操作する。
- セーブ形式は元のv7を引き継ぎ、保存キーで隔離する。旧版セーブのインポート機能は未提供。
- CIはビルド、lint、ルールテスト、デスクトップ／スマホ幅のブラウザテスト。既存コード由来のlint警告は残る。

## 初回検証メモ

- ルール・データ同一性、固定出目からの購入とターン交代、保留中の再ロール拒否、飲みの先送りと解消、成長率、保存分離、破損セーブ、40マスの座標連続性: 8件のテストを用意。
- ChromeのPC幅(1440px)・スマホ幅(390px)で、3D描画、カメラ切替、物件確認、平面切替、サイコロ移動、リロード再開を確認するE2Eを用意。
- PC操作テストで旧UIの無限拡縮アニメーションがクリック安定性を妨げたため、新版では枠の発光に変更。
- ブラウザ検証はソフトウェア描画を使用するため、フレームレートの実機評価には使わない。
