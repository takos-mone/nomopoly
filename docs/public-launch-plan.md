# 一般公開と収益化の計画

身内で遊ぶ形から、広告を載せて誰でも遊べる形へ移すための整理。
判断の根拠と、残っている作業をここにまとめる。

## 前提: 広告収益はほとんど立たない見込み

Google の掲載制限(Publisher Restrictions)は「アルコールの誤用」として
**過度な飲酒・一気飲み・競争的飲酒を好意的に描く内容**を明示的に対象にしている。
累計飲酒量を競い、一定量で脱落する本作はこの分類に入ると考えるのが妥当。

重要なのは、これが**規約違反ではない**こと。アカウントが止まる類の話ではなく、
「入札できる広告主が減る」扱いになる。ただし公式の説明では

- Google 広告は制限付きの内容には配信されない
- 入札がゼロになり、広告が一切表示されない場合もある

とされているため、**AdSense を貼っても収益はほぼ立たない**と見込んでおく。
広告枠は用意してあるが、収益の柱として当てにしない。

参考: [Google Publisher Restrictions](https://support.google.com/adsense/answer/10437795)

### 収益化の現実的な順序

1. **酒類メーカー・居酒屋チェーンとの直接タイアップ** — 題材との相性が最も良く、
   プログラマティック広告の制限も受けない。マスの店名や盤面の一角を提供する形が考えられる。
2. **投げ銭・サポート** — 規約上の制約がなく、遊んだ直後の満足度が高いタイミングで導線を置ける。
   結果画面に共有ボタンがあるので、その隣が自然。
3. **有料機能** — 追加ボードやカスタムカード。決済を入れると法務・税務の手当てが必要になる。
4. **広告** — 枠は用意済み。審査を通れば表示されるが、期待値は低い。

## 2つの版と、その理由

同じゲームを2つの名前で出している。ルール・盤面・3Dはまったく同じで、違うのは名前と絵柄だけ。

| | 飲もポリー | ハシゴロク |
|---|---|---|
| 用途 | 身内で遊ぶ | 一般公開・収益化 |
| URL | https://takos-mone.github.io/nomopoly/ | https://hashigoroku.web.app |
| 配信 | GitHub Pages(`main` へのpushで自動) | Firebase Hosting(`npm run deploy:hashigoroku`) |
| 名称 | 飲もポリー / NOMOPOLY | ハシゴロク / HASHIGOROKU |
| マスコット | 元のスプライトシート | 赤提灯(SVGで描き起こし) |
| 盤の配色 | 元の8色 | 飲み屋街の夜に寄せた8色 |
| 建物 | 小屋と宿 | 提灯と暖簾 |

一般公開する側で差し替えてあるのは、元の名称・キャラクター・盤の意匠が
実在の商品を強く想起させるため。**遊び方そのものは問題にならない**
(すごろく型の不動産ゲームの仕組みは保護の対象ではなく、原型は1904年の
The Landlord's Game まで遡る)。問題になるのは名前と絵柄なので、そこだけを
独自のものにすれば、ルール・盤面構成・3Dの作り込みはすべてそのまま活かせる。

### 混ざらないようにしてある

使うブランドの定義・絵柄・配色だけがビルドに入る。`#brand` / `#illustration` の
別名で実体を差し替え、画像は `app/brand-assets/<ブランド>/` に分けて、
使うほうだけを `dist` へ複製する。`public/` に置くと両方のビルドへ入ってしまう。

混ざっていないことは `app/tests/brand.test.ts` が実際にビルドして確かめる。
配色の取り違えは目で気づきにくいので、旧配色のコードが1つでも残っていたら落ちる。

## 実装済み

- **年齢確認** (`src/components/AgeGate.tsx`) — 20歳以上の確認と、遊ぶ前の約束ごと。
  確認結果は端末にのみ保存する。
- **責任ある飲酒の明示** — 一気飲みをしない、飲めない人に飲ませない、
  ノンアルでも成立する、飲んだら運転しない。設定画面とフッターにも常設。
- **利用規約・プライバシーポリシー** (`src/components/LegalModal.tsx`) —
  広告を載せる場合に掲示が求められる。本作はサーバーへ何も送っていないので、
  「集めていない」ことを具体的に書いている。
- **広告枠** (`src/components/AdSlot.tsx`) — 盤面を押し出さないよう高さを先に確保し、
  埋まらなければ畳む。`VITE_AD_CLIENT` を渡すまで無効。
- **共有導線** — 結果画面から順位と合計を共有できる。端末の共有シートが使えれば
  それを開き、無ければクリップボードへ写す。
- **オフライン対応とホーム画面アプリ化** — 一度開けば通信なしで遊べる。

## 残っている作業

### 自分で決める必要があるもの

- [ ] **連絡先の設定** — `src/brands/hashigoroku.ts` の `contact` が空。
      プライバシーポリシーから参照される。公開の前に実在のアドレスを入れる。
- [ ] **独自ドメイン** — いまは `hashigoroku.web.app`。取得したら Firebase Console から
      接続できる。`github.io` のサブパスや無料サブドメインのままだと広告審査で不利になりやすい。
- [ ] **AdSense の審査申請** — 独自ドメインと法務ページが揃ってから。
      上記のとおり通っても収益は期待しないこと。
- [ ] **リポジトリの公開範囲** — いまは public。差し替え前の名称と絵柄が履歴に残っており、
      一般公開版がそこから配信されている形が外から見える。配信物自体は無傷。
      気になるなら private にできるが、無料プランでは GitHub Pages が止まるため、
      飲もポリー側の配信先も Firebase へ移すことになる。

### 広告を出すことにしたら

- [ ] **EU向けの同意管理** — 広告Cookieを使う場合、EUからの訪問には同意取得が要る。
      日本国内に絞るなら不要だが、アクセス元を絞る手当てが必要。
- [ ] **アクセス解析** — 収益より先に「どこで離脱するか」を知りたい。
      個人情報を持たない構成を崩さない範囲で。

## オンライン対戦を見送った理由

移植ではなく再設計になるため、見送った。障害は次の4点。

1. **バックエンドが無い。** 現在は静的配信のみで動いており、
   部屋・同期・再接続を担う常駐サーバーが新たに要る。
2. **進行が再現できない。** 盤面の状態を更新する処理は5か所で `Math.random()` を直接呼んでいる
   (カードを引く / 交通の出目 / ランダムな指名 / ジャンケンの相手 / コイントス)。
   操作だけを配信すると各端末で結果がずれる。乱数を状態に持たせるか、
   サーバー側で確定させる作りに変える必要がある。
3. **同席が前提のカードがある。** ジャンケン、多数決、誕生日が一番近い人、
   罰ゲームで代替 — いずれも同じ場にいることを前提にしている。
4. **「実際に飲んでタップ」が成立しない。** ゲームの芯にある動作が自己申告になり、
   別の遊びになってしまう。

もし着手するなら、まず 2 の乱数の決定化から入るとよい。
これは単体で価値があり(不具合の再現とテストが楽になる)、
オンライン化の前提にもなる。
